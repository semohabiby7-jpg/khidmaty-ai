# Chapter 9: Your Own Library — Building a Prompt System in One Week

## The problem

Every prompt in this book will get lost if you leave it where you used it.

The description prompt ends up in an old chat, the reply prompt in a phone note, the ad prompt in a message you sent yourself on WhatsApp. A month later you can't find any of them, you rewrite from scratch — which is exactly what this book exists to prevent.

The problem isn't that you can't write a prompt. It's that you never **keep the one that worked**.

## The method: one file, five sections

A prompt library doesn't need software. It needs **one file** — paper or a Google Doc — split into five sections. Those five cover most of your work:

| Section | Prompts inside | Count |
|---|---|---|
| 1. Definition | Listing description, unit card, area summary | 3 |
| 2. Replies | Quick reply, full reply, objection reply | 4 |
| 3. Follow-up | Follow-up, revival, respectful close | 3 |
| 4. Advertising | Ad package, ad review, headlines | 3 |
| 5. Review | Pre-send review, objection analysis | 2 |

**Fifteen prompts** is your library. You don't need more, and you don't need fewer.

### The naming that saves you months

Random names are why prompts disappear. Use one fixed pattern:

`[type]-[goal]-[version]`

| Example | Meaning |
|---|---|
| `desc-1.1` | Description prompt, first version, first edit |
| `reply-quick-2.0` | Quick reply, complete second version |
| `followup-1.0` | Follow-up, first version |

The version number matters because you will edit. And when you edit, **keep the old one**. If the new version is worse, you roll back in a second instead of rewriting.

### The living-prompt rule

Every prompt in your library has to answer one question each week: **is this my best version?**

When you change it, write one line beneath it: "changed X because Y". That line is what stops you repeating the same mistake in two months. It is the difference between someone who uses tools and someone who builds a system.

### How to improve a prompt you already have

No prompt is perfect on the first try. But there is one reliable method: **test one change at a time**.

| Change | Example | What you measure |
|---|---|---|
| Role | "you are a writer" → "you are a writer selling to first-home families" | Is the tone closer? |
| Constraints | add "no number that isn't in the data" | Did the invented numbers disappear? |
| Format | "write a description" → "150 words + 3 headlines" | Is the output usable now? |
| Context | add "down payment and monthly" | Did client questions drop? |
| Standard | add "delete any line without information" | Shorter but better? |

If you change two things at once and the result improves, you won't know which one did it.

## The ready prompt: the prompt coach

> You are a prompt coach. I'll send you a prompt from my library; review it against five elements:
> 1. **Role:** specific or generic?
> 2. **Context:** does it contain the data it actually needs, or is something missing?
> 3. **Constraints:** length, tone, banned items?
> 4. **Format:** is the output shape defined?
> 5. **Standard:** is there a way for me to judge quality?
>
> Then: write the full improved version, tell me in three points what you changed and why, and suggest exactly one change for me to test next time.
>
> **My prompt:** [paste]

### Before / after

**Before:** "Write me an ad about the apartment."

**After:** "You are a real-estate copywriter in the Egyptian market. Unit: [data]. Write three short ads (three lines each) on three angles: problem, comparison, life. Each ends with one WhatsApp call to action. No hype, and no number that isn't in the data. If the information is insufficient, ask me before writing."

The difference isn't length — the second one is **incapable of producing generic copy**.

## Mistakes that destroy a prompt library

| Mistake | What happens | What to do |
|---|---|---|
| Keeping prompts inside chats | Lost at the first cleanup | One file |
| Random naming | You'll never find anything | type-goal-version |
| Editing without recording | You repeat the old mistake | A "changed X because Y" line |
| Copying prompts from the internet unchanged | Generic output | Adapt them to your data |
| Overlong prompts | The tool drowns in detail | Five elements only |
| Keeping only one version | No way back | Keep the old one |

## Chapter exercise (15 minutes)

1. Pick three prompts you actually use today.
2. Put them in one file, in five sections.
3. Name them with the fixed pattern.
4. Change exactly one prompt, and record the change in one line.
